## Samplesheet input

You will need to create a samplesheet with information about the samples you would like to analyse before running the pipeline. Use this parameter to specify its location. It has to be a comma-separated file with at least 4 columns, and a header row as shown in the examples below.

```bash
--input '[path to samplesheet file]'
```

| Column    | Description                                                                                                                                                                            |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sample`  | Custom sample name. This entry will be identical for multiple sequencing libraries/runs from the same sample. Spaces in sample names are automatically converted to underscores (`_`). |
| `fastq_1` | Full path to FastQ file reads 1. File has to be gzipped and have the extension ".fastq.gz" or ".fq.gz".                                                                                |
| `fastq_2` | Full path to FastQ file reads 2. File has to be gzipped and have the extension ".fastq.gz" or ".fq.gz".                                                                                |
| `match_dir` | Full path to match celescope scRNA-Seq directory. Required for tag assay. |

> [!NOTE]
> fastq_1, fastq_2, and match_dir must be full path. Relative path are not allowed.

### Multiple runs of the same sample

The `sample` identifiers have to be the same when you have re-sequenced the same sample more than once e.g. to increase sequencing depth. The pipeline will concatenate the raw reads before performing any downstream analysis.

## Running the pipeline

The typical command for running the pipeline is as follows:

```bash
nextflow run singleron-RD/nf-celescope \
 --input ./samplesheet.csv \
 --outdir ./outs \
 --barcode_fasta ./CLindex_TAG.fasta \
 --fq_pattern L25C15 \
 -profile tag,docker
```

### Tag-specific parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `barcode_fasta` | string | null | Path to a FASTA file containing the expected Tag sequences.|
| `fq_pattern` | string | `L25C15` | R2 read pattern. L: linker, C: tag barcode. Default for CLindex is L25C15. |
| `split_matrix` | boolean | `false` | Generate separate gene expression matrices for each assigned tag. |
| `UMI_min` | string | `auto` | Minimum UMI count threshold for tag assignment. Use `auto` for automatic detection or an integer. |
| `dim` | integer | `1` | Tag dimentions. Usually we use 1-dimentional tag. |
| `snr_min` | string | `auto` | Minimum signal-to-noise ratio for tag threshold. Use `auto` for automatic detection or a number. |
| `coefficient` | number | `0.1` | If `snr_min` is `auto`, minimum signal-to-noise ratio is calulated as `snr_min = max(median(snrs) * coefficient, 2)`. |
| `tag_threshold_method` | string | `snr` | Method for determining tag threshold: `snr` or `otsu`. |
| `linker_fasta` | string | null | Path to a FASTA file containing linker sequences. |

### Tag workflow

The tag workflow is specifically designed to analyze single-cell multiplexing data generated with kits such as CLindex™. Before initiating the tag workflow, you must first complete the corresponding single-cell transcriptome (scRNA-Seq) analysis using CeleScope.

The tag workflow consists of the following steps:

- **sample**: Automatically detect GEXSCOPE kit version from R1 reads.
- **barcode**: Demultiplex barcodes.
- **mapping_tag**: Align R2 reads to the tag barcode fasta.
- **count_tag**: Assign tag to each cell barcode and summarize.
- **analysis_tag**: Perform downstream analysis on the tag data.
- **split_tag**: Generate separate matrices for each tag (if `split_matrix` is `true`).

### Split Matrix Output Format

The matrices generated by the split_tag step follow the standard 10x Genomics-compatible format:

- `matrix.mtx.gz` — Sparse expression matrix
- `barcodes.tsv.gz` — List of identified cell barcodes
- `features.tsv.gz` — List of gene IDs and gene names

These outputs can be directly loaded into downstream analysis tools such as Seurat and Scanpy.

For detailed descriptions of outputs and the full list of available parameters, please refer to the [CeleScope documentation](https://github.com/singleron-RD/CeleScope).
