## Samplesheet input

You will need to create a samplesheet with information about the samples you would like to analyse before running the pipeline. Use this parameter to specify its location. It has to be a comma-separated file with at least 4 columns, and a header row as shown in the examples below.

```bash
--input '[path to samplesheet file]'
```

| Column    | Description                                                                                                                                                                            |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sample`  | Custom sample name. This entry will be identical for multiple sequencing libraries/runs from the same sample. Spaces in sample names are automatically converted to underscores (`_`). |
| `fastq_1` | Full path to FastQ file reads 1. File has to be gzipped and have the extension ".fastq.gz" or ".fq.gz".                                                                                |
| `fastq_2` | Full path to FastQ file reads 2. File has to be gzipped and have the extension ".fastq.gz" or ".fq.gz".                                                                                |
| `match_dir` | Full path to match celescope scRNA-Seq directory. Required for fusion assay. |

> [!NOTE]
> fastq_1, fastq_2, and match_dir must be full path. Relative path are not allowed.

### Multiple runs of the same sample

The `sample` identifiers have to be the same when you have re-sequenced the same sample more than once e.g. to increase sequencing depth. The pipeline will concatenate the raw reads before performing any downstream analysis.

## Running the pipeline

The typical command for running the pipeline is as follows:

```bash
nextflow run singleron-RD/nf-celescope \
 --input ./samplesheet.csv \
 --outdir ./outs \
 --fusion_genomeDir /path/to/fusion_genomeDir \
 -profile fusion,docker
```

Alternatively, you can build the fusion genome index on the fly by providing `fasta` and `fusion_pos` instead of `fusion_genomeDir`:

```bash
nextflow run singleron-RD/nf-celescope \
 --input ./samplesheet.csv \
 --outdir ./outs \
 --fasta ./fusion.fasta \
 --fusion_pos ./fusion_pos.txt \
 --genome_name fusion_genome \
 -profile fusion,docker
```

### Fusion-specific parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `fusion_genomeDir` | string | null | Fusion genome directory generated by `celescope fusion mkref`. If not provided, the pipeline will build it from `fasta` and `fusion_pos`. |
| `fasta` | string | null | Fusion gene FASTA file. Required if `fusion_genomeDir` is not provided. |
| `fusion_pos` | string | null | Fusion position file (tab-delimited, two columns: `tag` and `pos`). Required if `fusion_genomeDir` is not provided. |
| `genome_name` | string | genome | Name for the fusion genome directory built by MKREF. |
| `outFilterMatchNmin` | integer | 50 | Minimum alignment match length for STAR. |
| `out_unmapped` | boolean | false | Output unmapped reads. |
| `outFilterMultimapNmax` | integer | 1 | Maximum number of places allowed to match a read. |
| `starMem` | integer | 30 | Maximum memory that STAR can use (GB). |
| `STAR_param` | string | null | Additional STAR parameters. |
| `cutadapt_param` | string | null | Additional cutadapt parameters. |
| `minimum_length` | integer | 20 | Minimum read length for cutadapt. |
| `nextseq_trim` | integer | 20 | Quality trimming cutoff for NextSeq reads. |
| `overlap` | integer | 10 | Minimum overlap between adapter and read for cutadapt. |
| `flanking_base` | integer | 5 | Number of bases flanking the fusion position on both sides. |
| `min_query_length` | integer | 35 | Minimum query length for count_fusion. |
| `not_correct_UMI` | boolean | false | Do not perform UMI correction. |
| `read_threshold_method` | string | otsu | Method to find read threshold: auto, otsu, or hard. |
| `read_hard_threshold` | integer | null | User provided read threshold (used with hard method). |
| `umi_threshold_method` | string | otsu | Method to find UMI threshold: auto, otsu, or hard. |
| `umi_hard_threshold` | integer | null | User provided UMI threshold (used with hard method). |
| `auto_coef` | integer | 3 | Threshold coefficient for auto method. |
| `otsu_log_base` | number | 10 | Log base for Otsu's method. |

### Create fusion genome reference

The pipeline can automatically build the fusion genome index via the `MKREF` process when `fasta` and `fusion_pos` are provided. You can also build it manually:

```bash
celescope fusion mkref \
--genome_name BCR_ABL1_PML_RARA_all \
--fasta BCR_ABL1_PML_RARA_all.fasta \
--fusion_pos BCR_ABL1_PML_RARA_all_pos.txt
```

**Fasta file format:**
The fasta file contains sequences of known fusion genes. Each sequence name format is `{gene1}{exon}_{gene2}{exon}`:

```
>BCRe1_ABL1a2
ATGAG...
>BCRe13_ABL1a2
ATGGT...
```

**fusion_pos file format:**
A tab-delimited text file with two columns:

| Column | Description |
|--------|-------------|
| `tag` | Sequence name from the fasta file |
| `pos` | Fusion position (1-based coordinate indicating the end position of the first gene sequence) |

### Fusion workflow

The fusion workflow consists of the following steps:

- **sample**: Parse FASTQ files and generate sample metrics.
- **barcode**: Demultiplex barcodes and filter invalid R1 reads.
- **cutadapt**: Trim adapters and low-quality bases in R2 reads.
- **star_fusion**: Align reads to known fusion sites using STAR.
- **count_fusion**: Count reads and UMIs spanning fusion sites.
- **filter_fusion**: Correct UMI errors and filter background UMIs.
- **analysis_fusion**: Generate HTML report with t-SNE visualization.

For detailed descriptions of outputs and the full list of available parameters, please refer to the [CeleScope documentation](https://github.com/singleron-RD/CeleScope).
